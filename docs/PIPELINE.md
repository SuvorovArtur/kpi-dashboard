# KPI Dashboard — Pipeline и документация

## Архитектура

```
ЕЦУР (XLSX) → Импорт → Supabase (appeals) → Автоанализ (DeepSeek) → Дашборд (React)
                                  ↓
                          kpi_values (автосинк)
                                  ↓
                        KPI подробно (графики, история)
```

**Стек:** React 19 + TypeScript + Vite, Supabase (PostgreSQL + Edge Functions), DeepSeek API

---

## 1. Загрузка данных

### Источник
Выгрузка XLSX из ЕЦУР (Единый центр управления регионом). Содержит обращения граждан из систем: Добродел, ППМО, Инцидент, ПОС, ЕДС.

### Процесс импорта
1. Перейти на страницу **Обращения** → кнопка **Импорт XLSX**
2. Выбрать файл выгрузки ЕЦУР
3. Система автоматически:
   - Парсит XLSX, маппит колонки на поля БД
   - Дедуплицирует по `ecur_number` (номер ЕЦУР) — повторный импорт того же файла не создаст дубликатов
   - Записывает в таблицу `appeals`
   - Показывает результат: сколько новых, сколько пропущено

### Маппинг колонок XLSX → БД

| Колонка XLSX | Поле БД | Описание |
|---|---|---|
| Номер в ЕЦУР | `ecur_number` | Уникальный ключ дедупликации |
| Номер в источнике | `source_number` | Номер в Добродел/ППМО |
| Дата регистрации | `date` | Дата обращения |
| Направление | `direction` | Двор, Дороги, Освещение и т.д. |
| Синтетическая группа | `synth_group` | Группировка ЕЦУР |
| Факт | `fact` | Краткое описание |
| Подтема | `subtopic` | Детализация направления |
| Статус | `status` | В работе, Закрыта и т.д. |
| Куратор | `curator` | Ответственный куратор |
| Исполнитель | `executor` | Организация-исполнитель |
| ОМСУ | `omsu` | Орган местного самоуправления |
| Источник | `source` | Добродел, ППМО и т.д. |
| Тип сообщения | `message_type` | Проблемы, Предложения |
| Описание | `description` | Полный текст обращения |
| Адрес | `address` | Полный адрес (стандартизирован ЕЦУР) |
| Район | `district` | Район |
| Населённый пункт | `settlement` | Нас. пункт |
| Улица | `street` | Улица |
| Дом | `house` | Номер дома |

## 2. Анализ эмоционального окраса (ИСН)

### Автоматический запуск
После импорта при переходе на страницу **ИСН** система автоматически обнаруживает необанализированные обращения и запускает анализ батчами по 10 штук.

### Pipeline анализа
1. Из `appeals` выбираются записи с `sentiment_score IS NULL AND is_spam = false`
2. Вызывается Edge Function `analyze-sentiment` (Supabase)
3. Edge Function отправляет текст обращения в **DeepSeek API** (модель `deepseek-chat`)
4. Промпт v3.0 содержит:
   - Системную инструкцию для оценки по шкале 1–10
   - 8 калибровочных примеров
   - Few-shot примеры из отмодерированных обращений (`is_moderated = true`)
5. Результат (`sentiment_score` 1–10) записывается обратно в `appeals`
6. Прогресс отображается в реальном времени

### Шкала оценки

| Балл | Уровень | Цвет |
|---|---|---|
| 1–3 | Низкое напряжение | Зелёный |
| 4–6 | Среднее | Жёлтый |
| 7–8 | Острое | Оранжевый |
| 9–10 | Критическое | Красный |

### Формула ИСН
```
ISN_w = Σ(s²) / Σ(s)
```
Взвешенный индекс — острые обращения вносят непропорционально больший вклад.

### Модерация
На странице ИСН можно:
- Клик на столбик гистограммы → список обращений с этим баллом
- Клик на обращение → SlideOver с деталями
- Изменить балл вручную (кнопки 1–10) → `is_moderated = true`, используется как few-shot пример
- Исключить из расчёта ИСН (спам) → `is_spam = true`

**Важно:** `is_spam` исключает только из ИСН. Общие KPI (количество, на 1000 жителей) считают ВСЕ обращения.

## 3. Автоматические KPI

Рассчитываются на лету из таблицы `appeals`. При открытии страницы **KPI подробно** значения записываются в `kpi_values` для накопления истории.

### Активные KPI

| KPI | ID | Формула | Цель D360 |
|---|---|---|---|
| **ИСН** | `isn` | Σ(s²) / Σ(s), где s — балл (без спама) | ≤ 4 балл |
| **На 1000 жителей** | `appeals_per_1k` | Кол-во обращений / (Население / 1000) | ≤ 10 шт |
| **Горячие адреса** | `repeated_appeals` | Обращений с повторным адресом / Всего × 100 | ≤ 15% |
| **Отложенные** | `delayed_appeals` | Со статусом «Закрыта с отложенным» / Всего × 100 | ≤ 5% |

### Горячие адреса — логика подсчёта
- Группировка по ключу `address + direction`
- Если с одного адреса по одному направлению 2+ обращений — второе и последующие считаются «горячими»
- Адреса из ЕЦУР стандартизированы — точное совпадение строк достаточно
- Исключены слишком общие адреса (только «городской округ Мытищи» без улицы/дома)

### Горизонты планирования
Каждый KPI имеет три целевых значения, редактируемых в **Настройках**:
- **D90** — цель на 90 дней (краткосрочная)
- **D180** — цель на 180 дней (среднесрочная)  
- **D360** — цель на 360 дней (годовая)

Цветовая индикация: зелёный = цель достигнута, жёлтый = близко, красный = превышена.

## 4. Страницы дашборда

### Обзор (`/`)
- 5 KPI-карточек с фильтром по периоду (Неделя/Месяц/Квартал/Год/Всё)
- Клик на карточку → график динамики (7д/30д/квартал)
- Radar-график «Исполнение KPI» — все 5 метрик нормализованы в %
- Обращения по направлениям (horizontal bar)
- Обращения по дням (line chart)
- Горячие адреса — карточная сетка, клик → список обращений → SlideOver

### KPI подробно (`/kpi`)
- Скрыт по умолчанию, включается в Настройках
- 4 автоматических KPI с графиками динамики по дням
- Горизонты D90/D180/D360 с индикацией
- Таблица данных с экспортом CSV
- Ручное добавление значений

### Обращения (`/appeals`)
- Импорт XLSX
- Фильтры по направлению, статусу, дате
- Таблица с кликом → SlideOver
- Плашка «Последняя загрузка: до ДД.ММ.ГГГГ»

### ИСН (`/isn`)
- Светофор (зелёный/жёлтый/красный)
- 3 KPI-карточки (ИСН взвешенный, острые %, проанализировано)
- Гистограмма по баллам 1–10 с drill-down
- Средний балл по направлениям
- Недельный тренд
- Критические обращения (9–10) с копированием для Telegram
- Острые обращения (7–8)
- Модерация баллов в SlideOver

### Настройки (`/settings`)
- Целевые значения KPI (D90/D180/D360) — влияют на все карточки и графики
- Территориальные участки (CRUD)
- Население сельских территорий (для KPI «на 1000 жителей»)
- Разделы меню (toggle: KPI подробно)
- Экспорт CSV / PDF

## 6. Edge Functions (Supabase)

### analyze-sentiment
- **URL:** `https://dwrpellubzpjblmffmqv.supabase.co/functions/v1/analyze-sentiment`
- **Метод:** POST
- **Body:** `{ "batch_size": 10 }`
- **Логика:** берёт из `appeals` записи без `sentiment_score`, отправляет в DeepSeek, записывает результат
- **Ответ:** `{ "processed": N, "remaining": M }`
