# Мониторинг соцсетей — Pipeline анализа проблем

## Общая схема

```
Telegram-чаты жителей
        │
        ▼
┌──────────────────┐
│  Telethon бот    │  24/7, сервер 185.225.34.215
│  (bot.py)        │  Слушает все сообщения в подключённых чатах
└───────┬──────────┘
        │ мгновенно
        ▼
┌──────────────────┐
│  Supabase        │  tg_messages: chat_id, message_id, date, sender_name, text, reply_to_id
│  (PostgreSQL)    │
└───────┬──────────┘
        │ каждые 30 минут
        ▼
┌──────────────────┐
│  Анализатор      │  analyzer.py → DeepSeek API
│  (process_batch) │  Анализ КАЖДОГО ЧАТА ОТДЕЛЬНО
└───────┬──────────┘
        │
        ▼
┌──────────────────┐
│  tg_issues       │  Проблемы: title, summary, severity, status, location, direction
│  + tg_issue_msgs │  Связь проблем с сообщениями (M:N)
└───────┬──────────┘
        │
        ▼
┌──────────────────┐
│  Дашборд         │  socpulse.ru → Соцсети → Проблемы/Чаты
│  (React SPA)     │
└──────────────────┘
```

---

## Этап 1: Сбор сообщений (bot.py)

### Что делает
- Telethon userbot авторизован как @suvorov_ao
- Слушает `events.NewMessage(incoming=True)` из всех подключённых чатов
- Каждое сообщение длиннее 5 символов → сразу в Supabase

### Фильтры на этапе сбора
- Пропускаются: пустые сообщения, стикеры без текста, сообщения < 5 символов
- Текст обрезается до 2000 символов
- Сохраняется: chat_id, message_id, date, sender_name, text, reply_to_id

### Перезагрузка чатов
- Каждые 60 секунд бот запрашивает `tg_chats` из Supabase
- Новые чаты подхватываются автоматически (без перезапуска бота)
- Chat ID хранится с минусом (формат Telegram: -100XXXXXXXXXX)

## Этап 2: Анализ через DeepSeek (analyzer.py)

### Когда запускается
- Каждые 30 минут (ANALYSIS_INTERVAL = 1800 секунд)
- Берёт до 200 неанализированных сообщений из `tg_messages`
- Неанализированные = не привязанные ни к одной проблеме (LEFT JOIN tg_issue_messages IS NULL)

### Как анализирует
1. Группирует сообщения по чатам
2. **Для каждого чата отдельный запрос в DeepSeek** (чаты не смешиваются)
3. Результат — JSON с ветками проблем

### Параметры вызова API

```
Endpoint: https://api.deepseek.com/chat/completions
Model:    deepseek-chat
Temperature: 0.15 (низкая — детерминированный результат)
Max tokens: 2000
Response format: json_object
Timeout: 60 секунд
```

### Формат входных данных (user message)

```
Проанализируй сообщения за последние 30 минут.

[ЧАТ: Микрорайон Пироговский Мытищи ЧАТ | ID: -1001853464166]
[14:01] [MSG_ID:42] Анна: Добрый день всем
[14:03] [MSG_ID:43] Ольга: Кто-нибудь видел что на Центральной опять яма появилась? Прям у дома 15
[14:04] [MSG_ID:44] Дмитрий: @Ольга да, я вчера колесо там пробил. Огромная
```

## Этап 3: System Prompt (полный текст)

```
Ты — аналитик потока сообщений из Telegram-чатов Мытищинского городского округа.

ЗАДАЧА: Получи пакет сообщений за последние 30 минут. Проанализируй поток.
Отсей мусор. Выдели проблемы. Оцени критичность каждой.
Верни структурированный результат в формате json.
```

### ШАГ 1: ФИЛЬТРАЦИЯ МУСОРА

**Игнорировать (не включать в анализ):**
- Приветствия, прощания
- Стикеры, GIF, эмодзи без текста
- Короткие реакции без содержания («ок», «понял», «спасибо», «ахаха», «+1» без контекста)
- Реклама, спам, продажи
- Обсуждение погоды, пробок без жалоб
- Личные разговоры
- Политические дискуссии без привязки к муниципальной проблеме
- Информационные запросы («кто знает телефон...», «где находится...»)

**НЕ игнорировать:**
- Упоминание конкретной проблемы с адресом или локацией
- Жалобы на инфраструктуру, территорию, услуги
- Сообщения о ЧП, авариях, опасных ситуациях
- Обсуждения, где несколько человек подтверждают одну проблему
- Эмоциональные высказывания о бездействии властей
- Фото/видео проблем

### ШАГ 2: ГРУППИРОВКА В ВЕТКИ (THREADS)

Признаки одной ветки:
- Реплаи друг на друга
- Упоминание одного адреса/места
- Продолжение одной темы в пределах 10 минут
- Подтверждения других пользователей

### ШАГ 3: ОЦЕНКА КРИТИЧНОСТИ (шкала 1–10)

| Балл | Описание | Примеры |
|------|----------|---------|
| 1–2 | Нейтральное обсуждение | Бытовые вопросы |
| 3 | Фиксация проблемы без эмоций | «Яма на такой-то улице» |
| 4 | Лёгкое недовольство | «Опять не убрали», «когда наконец» |
| 5 | Умеренная жалоба с эмоциями | «Невозможно проехать», «достало» |
| 6 | Ощутимое недовольство, несколько человек | «Сколько можно», групповая жалоба |
| 7 | Выраженное раздражение | Обвинения в бездействии, капслок, «!!!!» |
| 8 | Сильное раздражение | Угрозы прокуратуры/СМИ, описание опасности |
| 9 | **АЛЕРТ** | Отчаяние, угроза здоровью/жизни, массовое возмущение |
| 10 | **АЛЕРТ** | Угрозы протеста/самосуда, ЧП в реальном времени |

**Модификаторы:**
- 5+ участников подтверждают проблему → **+1** к базовой оценке
- 10+ участников → **+2**
- Фото/видео проблемы → **+1**
- Призыв к коллективным действиям → минимум **7**
- ЧП в реальном времени → минимум **8**
- Угроза жизни/здоровью → минимум **9**

### ШАГ 4: ТЕМА И ЛОКАЦИЯ

**Темы:** дороги, благоустройство, мусор, вода, ЖКХ, экология, освещение, транспорт, безопасность, земля, энергетика, канализация, администрация, ЧП, другое

**Локация:** максимально точный адрес → район/улица/ЖК → «не указана»

## Этап 5: Постобработка (Python)

### Фильтры перед сохранением
1. **Score < 3** → пропускается (мусор/нейтральное)
2. **< 3 сообщений И < 2 участников И score < 8** → пропускается (слишком мало данных, кроме критических)

### Матчинг с существующими проблемами
- Загружаем активные проблемы из `tg_issues` (status = new/watching/escalated)
- Сравниваем: `location` (вхождение строки) + `direction` (topic)
- Если совпало → обновляем существующую проблему (добавляем сообщения, берём max severity)
- Если не совпало → создаём новую

### Автоэскалация
- Если `is_alert = true` (score ≥ 9) → статус автоматически ставится `escalated`

### Что сохраняется в tg_issues

| Поле | Описание |
|------|----------|
| title | Первые 100 символов summary |
| summary | Описание + ключевые цитаты |
| severity | 1–10 (берётся max при обновлении) |
| status | new → watching → escalated → resolved / ignored |
| direction | Тема (дороги, ЖКХ и т.д.) |
| location | Адрес/локация |
| message_count | Количество связанных сообщений |
| first_seen | Дата первого сообщения |
| last_seen | Дата последнего сообщения |

## Этап 6: Отображение на дашборде

### Вкладка «Проблемы»
- Карточки отсортированы по last_seen (новые сверху)
- Фильтры: Активные / Новая / Эскалация / Решена / Все
- Клик на карточку → раскрытие:
  - Summary с цитатами
  - До 5 связанных сообщений (кликабельные ссылки на Telegram)
  - Кнопки смены статуса

### Вкладка «Чаты»
- Карточка каждого чата: всего/сегодня сообщений
- Клик → раскрытие:
  - График по дням (столбики + количество участников)
  - Активные участники (топ-5)
  - Последние 5 сообщений (ссылки на Telegram)

### Ссылки на Telegram
```
https://t.me/c/{chat_id_without_100_prefix}/{message_id}
```
Формула: `abs(chat_id) - 1000000000000` → `chat_id` для URL

## Статусы проблем

```
new → watching → escalated → resolved
                          ↘ ignored
```

| Статус | Цвет | Описание |
|--------|------|----------|
| new | Красный | Только обнаружена |
| watching | Жёлтый | Взята на контроль |
| escalated | Красный | Требует немедленного внимания (авто при score ≥ 9) |
| resolved | Зелёный | Проблема решена |
| ignored | Серый | Ложное срабатывание |
